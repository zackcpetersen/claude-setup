# Watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `watch` skill and its `bin/watch` script: one on-disk registry of things the user is waiting on, checked on a cadence by the cheapest means, handled inside approved bounds, and raised only when a person has to act.

**Architecture:** `bin/watch` (Python 3, standard library, one file) owns the registry file and its lock, all time logic (quiet hours, business-day expiry, cadence, stale), the owner guard, and the script-backed checks (`gh` for PRs and deploys, Dagster GraphQL). A session cron job in the board's master session sends a short literal prompt: run `~/bin/watch tick`; empty output ends the turn; otherwise read `skills/watch/handle.md` and follow it. Handling dispatches haiku detect agents (Slack, email), sonnet judge agents (replies) and one research agent per requests-channel request, then handles or raises. Board rollover, sync, wrap, the Drafts-today hook and `/pr` register, mirror and re-arm watches.

**Tech Stack:** Python 3 standard library (`json`, `argparse`, `fcntl`, `subprocess`, `urllib.request`, `datetime`, `zoneinfo`, `unittest`), `gh` CLI, Claude Code session cron tools (`CronCreate`, `CronList`, `CronDelete`), Slack and Gmail MCP connectors.

**Spec:** `docs/superpowers/specs/2026-10-28-watch-design.md` (read it first, including its "Builder-check answers").

**Not in version one:** tracker (Jira) drafts. The spec's tick step 4 lists "tracker drafts"; handling here drafts Slack and email only, and a fired watch that needs a tracker comment raises with the ask instead.

## Global Constraints

- No em-dashes or en-dashes anywhere: code, comments, skill text, prompts, commit messages. Plain hyphens.
- Generic: nothing in `skills/watch/`, `bin/watch` or the tests names a company, person, channel, repo, ticket or real path. Machine values come from `~/.claude/CLAUDE.md` (`### Watches`, plus the Slack user id, `Email` line and watch-slack state file line of `### Work board`). Fixtures use `acme/app`, `U_ME`, `me@example.com`, `C_REQ`, `https://example.invalid/graphql`, time zone `America/Denver`.
- `bin/watch` is Python 3, standard library only, one file, no `.py` extension, executable, shebang `#!/usr/bin/env python3`.
- Tests use `unittest` only and never touch `~/.claude`: every test uses a `tempfile.TemporaryDirectory` registry and config, passed as arguments, `--registry`/`--config`, or `WATCH_REGISTRY`/`WATCH_CONFIG`/`WATCH_NOW`.
- Test command (only with the user's okay, per CLAUDE.md: no local test runs unless asked): `cd /Users/zack/Projects/claude-setup && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest bin/tests/test_watch.py -v`. The env var keeps `__pycache__` out of the repo (the `.gitignore` is not ours to change).
- Times are stored as UTC ISO 8601. All quiet-hours and business-day math converts to `zoneinfo.ZoneInfo(<Time zone line>)` first; never a fixed offset.
- Every subcommand holds the registry lock from load to save. The script never prints, logs or stores the Dagster token.
- Nothing is sent: Slack and email are drafts only, except threaded requests-channel replies under the user's own posting carve-out. The one write without a prompt is a merge the user pre-approved for that PR, run by the master.
- No-op tick is silent: the script prints nothing and exits 0, and the cron prompt stops with no text and no further tool call. `SKILL.md` and `handle.md` are not loaded on a no-op tick.
- Never edit `~/.claude/settings.json`, `~/.claude/CLAUDE.md` or `~/.claude/commands/watch-slack.md`. The install notes tell the user what to change.
- Commits use the repo style `[chore] <area>: <what>`, no Claude signature, and happen only after the user's okay. Never commit `.gitignore` or lock files.

## Review Focus

1. **Laptop asleep or session closed for hours, then the tick resumes:** a long gap must not raise every watch as stale or double-fire; each watch is checked once and raises at most once. Pinned by `test_long_gap_does_not_mass_stale` in Task 2.
2. **The detect agent reports the user's own message, or a ts older than the cursor:** nothing fires and the cursor never moves backward; the requests channel is the exception and still fires on the user's own top-level posts. Pinned by `test_update_fire_filters_self_messages`, `test_requests_channel_fires_on_self_and_holds_cursor` and `test_cursor_never_moves_backward` in Task 1.
3. **`gh` logged out, network down, or a Dagster error:** the check counts as an error, other watches still get checked, three in a row raise stale once, and no token or raw stderr reaches stdout or the registry. Pinned by `test_check_failure_counts_error_and_continues` and `test_dagster_token_never_printed` in Task 3.
4. **A PR in a repo with no CI checks:** an empty check rollup is green only when the merge state is `CLEAN`; otherwise it stays pending and never merges. Pinned by `test_rollup_state_cases` in Task 3.
5. **Registry hand-edited into bad JSON:** the script exits 2 with one line naming the file and never overwrites it. Pinned by `test_corrupt_registry_is_not_overwritten` in Task 1.

## Shared data shapes (all tasks)

Registry file (default `~/.claude/watches.json`):

```json
{"version": 1, "owner": null, "last_tick": null, "next_id": 1, "watches": []}
```

Watch row keys, as the spec names them: `id` (`w-<n>`), `kind`, `target` (dict), `expect`, `reply_brief`, `every`, `slow_every`, `after`, `expires`, `quiet`, `urgent`, `on_fire` (`verify` list, `draft` `reply`|`none`, `merge` null or `{"words", "at", "head_sha"}`, `then` null or a partial watch spec), `created`, `created_by` (`chat`|`board`|`pr`|`rollover`|`script`), `board_line`, `state`.
`state` keys: `status`, `cursor`, `last_check`, `last_ok_check`, `checks`, `errors` (consecutive), `note`, plus internal `slowed`, `stale_raised`, `dispatched_at`, `fired_at`, `result`, `draft`.
Durations are strings like `5m`, `60m`, `2h`.

Target keys per kind: `slack-thread` `{channel, thread_ts}`; `slack-dm` `{channel}`; `email-thread` `{thread_id}`; `pr` `{repo, number}`; `deploy` `{repo, sha}`; `dagster-run` `{run_id, expected_hours?}`; `dagster-backfill` `{backfill_id, expected_hours?}`; `requests-channel` `{channel, user}`.

Tick output, one JSON line, printed only when a list is non-empty:

```json
{"fired": [{"id", "kind", "event", "result", "target", "expect", "reply_brief", "on_fire", "urgent", "board_line"}],
 "due": {"slack": [{"id", "kind", "target", "cursor"}], "email": []},
 "stale": [{"id", "reason"}],
 "expired": [{"id", "rule", "phase"}]}
```

Exit codes: `0` ok, `2` invalid input or corrupt registry, `3` tick refused (another owner).

**Interfaces:**
- Consumes: nothing.
- Produces (module-level in `bin/watch`):
  - `KINDS: dict[str, dict]` with keys `every`, `slow_every`, `expires`, `connector` (`"slack"`, `"email"` or `None`), `quiet`. Values: `slack-thread`, `slack-dm` `10m`/`60m`/`reply`/`slack`/True; `email-thread` `20m`/`60m`/`reply`/`email`/True; `pr` `15m`/`15m`/`until-closed`/None/True; `deploy` `30m`/`30m`/`two-days`/None/True; `dagster-run`, `dagster-backfill` `5m`/`5m`/`until-terminal`/None/False; `requests-channel` `10m`/`10m`/`never`/`slack`/True.
  - `STATUSES = ("armed", "fired", "handled", "raised", "expired", "paused", "stopped")`, `TERMINAL = {"handled", "raised", "expired", "stopped"}`.
  - `class WatchError(Exception)` (exit 2).
  - `load_config(path: Path) -> dict` with keys `registry`, `tz` (`ZoneInfo`), `tick` (timedelta), `quiet` (`{"start": time, "end": time, "weekends": bool}`), `business` (`{"start": time, "end": time}`), `self_ids` (set: the Work board `Slack user id` plus the email address found in the Work board `Email` line), `connectors` (`{"slack": str, "email": str}`), `requests` (`{"channel", "user", "state_file"}` or None; `user` is the Work board Slack user id, `state_file` the Work board `Watch-slack state file` line; a Requests channel line without that state file line raises `WatchError`), `dagster` (`{"url", "env_file", "token_var"}` or None), `deploy_rules` (`{repo: rule dict}`). A missing `Time zone` line raises `WatchError`.
  - `parse_duration(text: str) -> timedelta` (`s`, `m`, `h`, `d`).
  - `parse_deploy_rule(text: str) -> dict`: `workflow <name> on <branch>` gives `{"type": "workflow", "name", "branch"}`; `release-tag` gives `{"type": "release-tag"}`; `branch <name>` gives `{"type": "branch", "name"}`; else `WatchError`.
  - `locked_registry(path: Path) -> ContextManager[dict]`: takes `fcntl.flock(LOCK_EX)` on `<path>.lock`, loads (missing file gives the empty skeleton; bad JSON raises `WatchError` naming the path), yields the dict, and on a clean exit writes `<path>.tmp` then `os.replace`; on an exception it writes nothing. Every subcommand, `tick` included, runs its whole read-modify-write inside one `locked_registry`.
  - `add_watch(reg: dict, spec: dict, now: datetime, cfg: dict) -> str`: validates `kind` and `target` keys, fills defaults from `KINDS`, sets `status = "armed"`. Starting cursor: `spec["cursor"]` when given; else for Slack kinds the add time as epoch seconds (`f"{now.timestamp():.6f}"`); `email-thread` without a cursor raises `WatchError` (the caller passes the newest message id); `requests-channel` uses the state file's content, or when the file is missing writes the add time there so no backlog is processed. If a non-terminal watch with the same `kind` and `target` exists, returns its id and changes nothing.
  - `advance_cursor(kind: str, old: str | None, new: str | None) -> str | None`: Slack kinds compare as floats and keep the larger; other kinds take `new` when not None.
  - `filter_self(messages: list[dict], self_ids: set[str]) -> list[dict]` (drops entries whose `author` is in `self_ids`).
  - `update_watch(reg, wid, now, cfg, *, status=None, cursor=None, checked=False, error=None, note=None, draft=None, messages=None, merge=None, head=None, board_line=None) -> dict`:
    - `checked` sets `last_check`, `last_ok_check`, `checks += 1`, `errors = 0`, clears `dispatched_at` and `stale_raised`; `error` sets `last_check`, `errors += 1`, `note`.
    - `messages` (a detect report): for every kind except `requests-channel`, run `filter_self`, advance the cursor to the newest ts or id reported, and when any message remains set `status = "fired"`, `fired_at`, `result = {"messages": [...]}`. For `requests-channel`, keep only messages whose author is `target.user` and whose ts is above the cursor, do not run `filter_self`, and do not move the cursor; it fires with those messages. Its cursor (and the state file) moves only through a later `cursor=` call made after each request is handled.
    - `merge` with `head` sets `on_fire.merge = {"words": merge, "at": now, "head_sha": head}`; `merge` without `head` raises `WatchError`; only `pr` watches accept it.
    - `board_line` sets the row's `board_line`. Unknown id raises `WatchError`.
  - `format_list(reg: dict, cfg: dict, now: datetime) -> str`: one line per non-terminal watch `<id> <kind> <status> next <HH:MM> last ok <HH:MM or never> "<expect, 60 chars>"` in local time, then `tick: last <HH:MM> by <owner>`, and `tick not running` when `last_tick` is older than 3 tick intervals.
  - `main(argv: list[str]) -> int`: global flags `--registry`, `--config`, `--now` (ISO with offset; env `WATCH_REGISTRY`, `WATCH_CONFIG`, `WATCH_NOW`; defaults: config `~/.claude/CLAUDE.md`, registry from config, then `~/.claude/watches.json`). Subcommands: `add [--file PATH | --json STR]` (stdin when neither), `list`, `status [ID]` (JSON), `stop ID`, `pause` (every `armed` becomes `paused`), `resume` (every `paused` becomes `armed`), `update ID [--status S] [--cursor C] [--checked] [--error MSG] [--note TEXT] [--draft ID] [--messages-file PATH] [--merge WORDS --head SHA] [--board-line TEXT]`. `tick` and `add --then-of` come in Tasks 2 and 3.

### Task 2: Time logic, tick, owner guard and the silent no-op

**Files:**
- Modify: `bin/watch`
- Test: `bin/tests/test_watch.py`

**Interfaces:**
- Consumes: everything Task 1 produces.
- Produces:
  - Constants `STALE_ERRORS = 3`, `AGENT_TIMEOUT = timedelta(minutes=10)`, `FIRED_TIMEOUT = timedelta(minutes=10)`, `REQUEST_FIRED_TIMEOUT = timedelta(minutes=60)` (a requests-channel watch stays fired while its research agents run), `OWNER_WINDOW = 2` (tick intervals).
  - `class NotOwner(Exception)` (exit 3, one stderr line `tick refused: owned by <owner>, last tick <HH:MM>`).
  - `in_quiet_hours(now: datetime, cfg: dict) -> bool`: converts `now` to `cfg["tz"]`; the window may wrap midnight; Saturday and Sunday are quiet when `weekends` is True.
  - `add_business_days(start: datetime, n: int, cfg: dict) -> datetime`: in `cfg["tz"]`, move `start` forward to the next moment inside business hours on a weekday (unchanged if already inside), then step `n` weekdays keeping the wall-clock time, building the result with `datetime.combine(day, wall_time, tzinfo=cfg["tz"])` so a DST change keeps the local hour.
  - `expiry_state(watch: dict, now: datetime, cfg: dict) -> str | None`: `reply` gives `"soft"` from `created` + 1 business day and `"hard"` from + 5; `two-days` gives `"hard"` from `created` + 48h; `until-terminal` gives `"soft"` once `now - created` exceeds the target's `expected_hours`; `until-closed` and `never` give None; an ISO time gives `"hard"` once passed.
  - `cadence(watch: dict) -> timedelta` (`slow_every` when `state.slowed`, else `every`).
  - `is_due(watch: dict, now: datetime, cfg: dict) -> bool`: status `armed`; not (`quiet` and `in_quiet_hours`); `after` passed or unset; no `dispatched_at`; `last_check` None or `now - last_check >= cadence`.
  - `stale_reason(watch: dict, now: datetime) -> str | None`: `"3 failed checks in a row: <note>"` when `errors >= STALE_ERRORS`; `"detect agent did not report"` when `dispatched_at` is older than `AGENT_TIMEOUT`; `"fired but not handled"` when status `fired` and `fired_at` older than `FIRED_TIMEOUT` (`REQUEST_FIRED_TIMEOUT` for `requests-channel`). Elapsed wall time alone never makes a watch stale (quiet nights, sleeping laptops); this is how the spec's "no successful check in three cadences" is counted. A tick that stopped running shows as `tick not running` in `list` and is fixed by `arm`.
  - `run_check(watch: dict, cfg: dict) -> tuple[str, str | None, dict]`: a stub here; Task 3 fills it. Contract: `(fingerprint, event or None, result)`; raises on failure.
  - `short_error(e: Exception, cfg: dict) -> str`: class name plus the first 120 characters of the message, with the Dagster token value (when set in `os.environ`) replaced by `***`.
  - `tick(reg: dict, cfg: dict, now: datetime, *, session: str, take: bool = False) -> dict` (report shape in "Shared data shapes"). `main` runs it inside one `locked_registry`, so adds and updates from peers wait for the tick to finish instead of being overwritten.
  - CLI: `tick [--take] [--session NAME]`.

Tick algorithm (order matters):

```text
if reg.owner and reg.owner != session and not take
   and reg.last_tick and now - reg.last_tick < OWNER_WINDOW * cfg.tick: raise NotOwner
reg.owner = session; reg.last_tick = now
for w in non-terminal watches:
    phase = expiry_state(w)
    if phase == "hard": status = expired; report.expired += {id, rule, "hard"}; continue
    if phase == "soft" and not slowed: slowed = True; report.expired += {id, rule, "soft"}
    reason = stale_reason(w)
    if reason and not stale_raised:
        stale_raised = True; report.stale += {id, reason}
        if reason is the agent one: dispatched_at = None; errors += 1    # checked again next cadence
    if status == fired or not is_due(w): continue

    except Exception as e: errors += 1; last_check = now; note = short_error(e, cfg); continue
    mark checked; if event and fp != cursor: status = fired; fired_at = now; state.result = result; report.fired += row
    cursor = fp
print one compact JSON line only if any report list is non-empty
```
